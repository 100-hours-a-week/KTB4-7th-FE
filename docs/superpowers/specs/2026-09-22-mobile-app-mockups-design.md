# 모바일 앱 목업 확장 설계

## 목표

맴매 프론트엔드를 PC에서는 중앙의 스마트폰 프레임으로, 실제 모바일에서는 전체 화면으로 보이게 한다. 회원가입 API 연동은 변경하지 않고, 로그인·알림·마이페이지·매출 분석 화면은 후속 API 연동을 고려한 정적 목업으로 제공한다.

## 범위와 제약

- `/signup`의 API 주소, 요청·응답 타입, `Signup-Token` 헤더, 오류 처리와 단계 전환은 변경하지 않는다.
- 로그인, 알림, 프로필, 매출 업로드와 분석은 네트워크 요청 없이 fixture만 사용한다.
- 문서화되지 않은 인증, 세션, 매출 분석 API는 추가하지 않는다.
- PC 폭이 431px 이상이면 폭 430px의 기기 프레임 안에서 본문만 스크롤한다.
- 모바일 폭에서는 프레임·외부 배경을 제거하고 뷰포트 전체를 앱으로 사용한다.

## 화면 흐름

### 비로그인

- 랜딩(`/`): 서비스 가치와 회원가입·로그인 진입점.
- 로그인(`/login`): 이메일·비밀번호 입력 UI와 데모 로그인 버튼만 제공한다. 로그인 성공을 가장한 로컬 화면 전환이나 토큰 저장은 하지 않는다.
- 회원가입(`/signup`): 기존 3단계 API 흐름을 유지한다.

### 로그인 후 목업

- 솔루션 요약(`/solution`): 제공된 솔루션 카드 또는 솔루션 없음 빈 상태를 표시한다.
- 솔루션 상세(`/solution/:solutionId`)와 AI 채팅(`/solution/:solutionId/chat`): 기존 fixture를 사용한다.
- 저장됨(`/my-solutions`): 저장한 솔루션 목록 및 빈 상태를 표시한다.
- 알림(`/notifications`): 읽음/읽지 않음 구분을 가진 알림 목록을 표시한다.
- 마이페이지(`/profile`): 매장 기본 정보, 계정 정보, 환경 메뉴를 표시한다.
- 매출 업로드(`/sales/upload`): 파일 선택 전·파일 선택 후·업로드 완료 상태를 로컬 상태로 표시한다. 파일은 서버에 전송하지 않는다.
- 매출 분석(`/sales/analysis`): 업로드 목업 데이터에서 만든 요약 지표와 추이를 표시한다.

## 구조

- `entities/solution/model`: 기존 솔루션 fixture 유지.
- `entities/dashboard/model`: 로그인 사용자, 알림, 저장 솔루션, 매출 분석 fixture와 타입을 둔다.
- `shared/ui`: 앱 프레임, 상단 헤더, 하단 탭, 빈 상태, 섹션 카드 등 재사용 UI를 둔다.
- `pages`: 페이지 조합과 페이지별 로컬 상호작용만 담당한다. 목업 fixture를 직접 변경하지 않는다.
- `AppShell`: `title`과 현재 화면의 주요 행동을 받으며, 기기 프레임 내부에서 헤더·스크롤 본문·하단 탭을 구성한다.

## 레이아웃과 접근성

- 기기 프레임은 검은 테두리, 노치, 홈 인디케이터, 그림자를 갖지만 본문을 가리지 않는다.
- 헤더와 하단 탭은 기기 프레임 안에서 고정되고, `.app-content`만 세로 스크롤한다.
- 버튼은 최소 44px 높이, 아이콘 버튼은 이름을 가진 `aria-label`을 둔다.
- 카드·입력·모달은 공통 색상과 포커스 스타일을 사용한다.
- 빈 상태는 다음 행동으로 연결되는 버튼을 제공한다.

## 상태와 오류

- 회원가입: 현재 필드 오류·서버 오류·가입 토큰 만료 표시를 보존한다.
- 매출 업로드: 미선택, 유효하지 않은 파일, 선택 완료의 로컬 안내 상태를 제공한다.
- 솔루션·저장됨·알림: fixture가 비어 있는 경우 각각 친절한 빈 상태를 표시한다.
- 모든 새 화면은 API 실패 상태를 만들지 않는다. API를 호출하지 않기 때문이다.

## 검증

- AppShell: PC 프레임과 모바일 전체 화면의 배치 규칙을 클래스 단위로 검증한다.
- 새 페이지: 핵심 제목, 빈 상태, 목업 상호작용을 테스트한다.
- 회원가입 API 테스트를 유지한다.
- PR 전 `npm run test -- --run`, `npm run lint`, `npm run build`를 실행한다.
